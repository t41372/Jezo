# Brief: designing Jezo for offline sync between devices, ahead of time

Read-only research and design. Do not change any files. Read the repository (AGENTS.md, docs/design/storage.md, backend.md, undo.md, memory.md, concept.md, src/main/workspace/*, src/main/agent/undo.ts, packages/pi-memory/src/memory.ts) and research on the web. Today is 2026-09-30.

## Context
Jezo is an open-source, local-first desktop app (Electron + TypeScript, macOS first) for managing a life: todos, goals, notes, calendar, habits, long-term memory. Built for people with ADHD. One user. An embedded agent (pi coding agent SDK) reads and edits the workspace like a coding agent: files plus tools. The workspace directory (~/Jezo) is the source of truth: one directory per plugin, items as markdown files with YAML frontmatter and immutable ids (t-xxxx), manifests (JSON Schema), pi session transcripts as JSONL, memory as md files plus a forgotten.yaml tombstone list, automations as md files. The GUI edits frontmatter key by key with a hash check; outside edits (the user in Typora, the agent with bash) are detected with fs.watch plus rescans. Undo is a log outside the workspace of files the agent changed.

Decisions Tim made today:
- Editing the workspace in Typora/Obsidian is a side benefit, not a product promise. Formats are defaults, not principles.
- There is no phone app yet, but one is likely later. It should work offline on its own and merge with the desktop. Tim wants to design the architecture for offline sync now, so it isn't painful later. If sync is built, he'd like to use peer-to-peer technology like iroh (https://iroh.computer).
- Hard constraints: no servers run by the project, no paid infrastructure, no Docker. Privacy is central: user data must not sit readable on a third party's servers. (Relays that only forward end-to-end encrypted traffic may be acceptable; say so explicitly where it matters.)
